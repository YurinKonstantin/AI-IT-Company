# AI IT-Company — инструкция пользователя

Версия документа: 1.0 · Обновлено: 2026-08-02

Практический гайд: как эффективно работать с локальным мультиагентным конвейером.

---

## 1. Быстрый старт

1. Установите [.NET 10 SDK](https://dotnet.microsoft.com/download) (версия решения — `net10.0`).
2. Установите [Ollama](https://ollama.com) и скачайте хотя бы одну модель кодинга (например `qwen2.5-coder:7b`).
3. Соберите и запустите приложение `AI IT-Company` (WinUI 3).
4. Откройте **Настройки → Провайдеры AI**: URL Ollama (обычно `http://localhost:11434`), нажмите проверку связи.
5. На странице **Агенты** назначьте модели ролям или примените пресет **Compact** / **Balanced**.
6. Перейдите в **Чат**, выберите режим (или **Авто**), введите задачу, нажмите запуск.

Опционально: OpenRouter / LM Studio / ONNX — в тех же Настройках, если нужны облачные или локальные альтернативы Ollama.

---

## 2. Выбор режима

| Ситуация | Режим |
|----------|--------|
| Не уверены, что делать | **Авто** — Interpreter классифицирует intent |
| Новый проект с нуля | **Создать новый** |
| Есть код, нужно улучшить | **Улучшить** (+ папка проекта) |
| Красная сборка / баг | **Исправить ошибку** (+ папка) |
| Только README / архитектура | **Задокументировать** (+ папка) |
| Разбор без правок кода | **Проанализировать** (+ папка) |
| Только ТЗ, без кода | **Только ТЗ / архитектура** |

Чеклист перед стартом:

- [ ] Приложение WinUI / API / Console / MAUI / служба / игра MonoGame — укажите в промпте или доверьтесь Авто.
- [ ] Для Improve / Fix / Document / Analyze выбран **путь к существующему проекту**.
- [ ] Режим **не** «Авто», если нужен жёсткий маршрут (ModeLocked).

---

## 3. Как писать промпт

Хорошо:

- Стек и тип: «WinUI 3 приложение-заметки с SQLite», «MonoGame 2D платформер DesktopGL».
- Критерии: «кнопка Добавить сохраняет текст», «сборка зелёная».
- Границы: «без сети», «один экран».

Плохо:

- «Сделай крутую игру как GTA» — слишком широко.
- Пустой промпт — конвейер не стартует осмысленно.

Для **Улучшить**: что именно (UI, производительность, баг X).  
Для **Авто**: можно короче — модель выберет режим и тип.

Вложения Cursor-стиля: `@file путь` или `@folder путь` — приоритетный контекст для агентов.

---

## 4. Пресеты моделей

| Пресет | Когда |
|--------|--------|
| **Compact** | Слабый ПК, 7b-класс, быстрее итерации |
| **Balanced** | 14b на Architect/кодерах — выше качество ТЗ и кода |

Documenter / Analyst / Secretary лучше на **текстовых** моделях (не обязательно coder).  
Слабая модель на Architect даёт размытое ТЗ — не экономьте здесь при сложных проектах.

---

## 5. Рабочий цикл «Создать новый»

1. Interpreter фиксирует тип/режим.
2. Architect пишет ТЗ и этапы.
3. Scaffolder создаёт каркас (`dotnet new`).
4. Кодеры (Backend / Frontend / Game / Tests) по scope этапа.
5. Builder: restore → build → при нужде NuGet auto-add → acceptance.
6. При ошибке — ErrorFixer (ограниченное число попыток).
7. Успех → git commit этапа; провал → откат / skip зависимых.
8. Secretary → `REPORT.md`.

Смотрите **Дашборд** во время прогона; упавший этап можно **повторить** (Retry), не игнорируйте Failed.

---

## 6. Improve / Fix

- Обязательно укажите **папку проекта**.
- Перед правками может создаваться бэкап.
- Читайте `build_log` на Дашборде / в событиях Чата.
- Если включён режим ревью (**Настройки**): правки попадают в **Изменения** — Apply / Reject по файлам.
- Не жмите «применить всё» вслепую: смотрите дифф, после Apply проверьте сборку.

Внешний редактор: путь в Настройках → открытие файла из Изменений.

---

## 7. Document / Analyze

| Режим | Появится | Не ждите |
|-------|----------|----------|
| Document | `README.md`, `ARCHITECTURE.md` | массового переписывания кода |
| Analyze | `ANALYSIS.md` | автоматических фиксов |

После — краткий отчёт Secretary.

---

## 8. Игры MonoGame

1. Режим Create + тип игры (или Авто с формулировкой «MonoGame»).
2. Artist кладёт спрайты в `Content/Sprites`, манифест и `Content.mgcb` / `LOADING.md`.
3. GameCoder пишет игру с загрузкой текстур.
4. В **Настройках** можно включить image-gen (OpenRouter/Ollama); при сбое — procedural fallback.
5. После сборки проверяйте наличие PNG и зелёный build.

---

## 9. Изменения (@file, Apply/Reject)

- Чипы `@file` / `@folder` в Чате добавляют пути в контекст.
- Improve/Fix: режим ревью Always / ImproveFix / Never — в Настройках.
- Правило: **прочитал дифф → Apply → verify** (build / smoke).
- Reject — если патч вредный; можно уточнить промпт и перезапустить этап.

---

## 10. Биржа (Фриланс)

1. **Настройки** или вкладка: источники (Demo / GitHub bounties / feed URL), фильтры, rate limit.
2. **Охота** — список офферов со score и объяснением.
3. По умолчанию **Accept вручную** — безопаснее.
4. Авто-accept (opt-in) только запускает **внутренний** пайплайн, **не** отклик на бирже.
5. После выполнения поставьте **оценку 1–5** — так калибруется скоринг.
6. Режим simulation-only — без реальных Accept в прод-смысле, для тестов.
7. Смотрите win-rate, топ тегов и audit на вкладке.

---

## 11. Типичные ошибки

| Ошибка | Что сделать |
|--------|-------------|
| Improve без папки | Выберите путь к проекту |
| Пустой промпт | Опишите задачу конкретно |
| Слабый Architect | Смените модель / пресет Balanced |
| Failed stage без Retry | Повторите этап, смотрите лог |
| Apply all вслепую | Читайте диффы на Изменениях |
| Нет Ollama | Запустите сервис, проверьте URL |
| Биржа пустая | Включите Demo или укажите feed / GitHub PAT |

## 12. Где лежат данные

Корень: `%USERPROFILE%\AiItCompany\`

| Путь | Содержимое |
|------|------------|
| `Output\` | Созданные проекты и прогоны |
| `Output\Freelance\{id}\` | Принятые задачи биржи |
| `aiitcompany.db` | SQLite (сессии, офферы, outcomes) |
| `Logs\` | Логи приложения |
| бэкапы | копии перед Improve/Fix (если включены) |

## English summary

Local WinUI multi-agent C# pipeline (Ollama / LM Studio / OpenRouter / ONNX). Modes: Auto, Create, Improve, Fix, Document, Analyze, Plan. Tabs: Chat, Dashboard, Changes, Freelance, Agents, Models, Logs, Settings, Help. Freelance: hunt → score → accept → rate → stats (no silent marketplace bids). Data under `%USERPROFILE%\AiItCompany\`. See FEATURES.md for the feature catalog.
