AI IT Company

Локальный ИИ-конвейер, который заменяет команду разработки C#-приложений и игр.
A local AI pipeline that replaces a C# application and game development team.
一个能够替代 C# 应用程序及游戏开发团队的本地 AI 流水线。

💡 Идея(Idea, 主意)

AI IT Company — это desktop-приложение на WinUI 3, которое эмулирует работу полноценной IT-компании силами специализированных ИИ-агентов. Вместо одной универсальной модели, которая пытается делать всё сразу, каждую роль в проекте выполняет отдельный агент, а к каждому агенту можно привязать свою языковую модель — оптимальную именно для его задачи.
Ключевой принцип — полностью локальная работа. Всё выполняется на вашем компьютере через Ollama, без обращения к облачным API. Это означает:
This is a WinUI 3 desktop application that simulates the operations of a full-fledged IT company using specialized AI agents. Instead of a single all-purpose model attempting to handle everything at once, each project role is performed by a dedicated agent, and a specific language model—optimized for that agent's particular task—can be assigned to each one.
The key principle is fully local operation. Everything runs on your computer via Ollama, without calling cloud APIs. This means:
这是一个 WinUI 3 桌面应用程序，它利用专门的 AI 智能体（AI agents）来模拟一家成熟 IT 公司的运作流程。该应用不依赖单一的通用模型来包揽所有任务，而是为每个项目角色分配专门的智能体，并针对该智能体的具体任务为其指定特定的语言模型（经过相应优化）。
其核心原则是完全本地化运行。所有操作均通过 Ollama 在您的计算机上执行，无需依赖云端 API。这意味着：

✅ Бесплатно — никаких подписок, токенов и биллинга.

✅ Приватно — ваш код и идеи никогда не покидают ваш ПК.

✅ Независимо — работает даже без интернета (после загрузки моделей).

✅ Гибко — под каждую задачу можно выбрать модель, оптимальную по скорости/качеству/ресурсам.

🎯 Функционал

Мультиагентная архитектура

В проекте задействованы специализированные ИИ-агенты, каждый — со своей ролью, системным промптом и (опционально) собственной моделью:



Агент	Роль

🧭 Интерпретатор	Разбирает запрос пользователя, определяет тип и режим работы

🏛 Архитектор	Составляет ТЗ и разбивает работу на независимые этапы

🏗 Скаффолдер	Создаёт каркас проекта через dotnet new

⚙ Backend-Кодер	Пишет серверную часть, сервисы, работу с данными

🎨 Frontend-Кодер	Пишет WinUI 3 (XAML + MVVM через CommunityToolkit.Mvvm)

🎮 Game-Кодер	Пишет игры на MonoGame (DesktopGL)

🧪 Тестировщик	Генерирует юнит-тесты (xUnit + FluentAssertions + Moq)

🔧 Сборщик	Выполняет dotnet build, фиксирует результат в Git

🩹 Исправитель ошибок	Анализирует лог сборки и патчит код автоматически

📝 Секретарь	Формирует итоговый отчёт по проекту

Поэтапная разработка с версионированием

Работа над проектом идёт этапами, а не одним монолитным ответом модели:



Архитектор составляет ТЗ и разбивает его на этапы с явными зависимостями и критериями приёмки. Каждый этап должен оставлять программу в рабочем состоянии — пусть и с урезанным функционалом.

Кодеры параллельно реализуют текущий этап по scope (Backend / Frontend / Game / Tests).

Сборщик выполняет dotnet build.

Если сборка упала — Исправитель анализирует лог и делает до 3 попыток авто-исправления.

Успешный этап фиксируется как отдельный git-коммит. При провале — откат к последнему рабочему состоянию.

Этапы, зависевшие от провалившегося, отмечаются пропущенными; независимые этапы продолжают выполняться.

По завершении Секретарь сохраняет REPORT.md с полной сводкой работы.

Управление моделями и провайдерами

В **Настройки → Провайдеры AI** можно выбрать и настроить:

| Источник | Где выполняется | Что указать |
|----------|-----------------|-------------|
| **Ollama** (по умолчанию) | Локально | URL (обычно `http://localhost:11434`), тег модели на странице Агенты |
| **OpenRouter** | Интернет | Base URL + API key (хранится в **Windows Credential Locker**, не в SQLite) |
| **ONNX / Windows ML** | Локально (Microsoft.ML.OnnxRuntimeGenAI.WinML) | Папка моделей (по умолчанию `%USERPROFILE%\AiItCompany\Models`); ModelName = имя подпапки с `genai_config.json` |

На странице **Агенты** у каждого агента выбирается источник: `Ollama` | `OpenRouter` | `ONNX`.

Через встроенный интерфейс моделей Ollama можно:

Просматривать список доступных моделей Ollama.

Скачивать новые модели одним кликом (с прогрессом загрузки).

Удалять ненужные модели.

Для каждого агента отдельно выбирать: провайдер, модель, температуру, контекстное окно, лимит токенов, таймаут.

Переопределять системные промпты любого агента (или использовать дефолтные из кода).

Установите .NET 10 SDK и Ollama.

Загрузите модель, например:

bash

bash

Назначьте выбранную модель нужным агентам и опишите задачу в главном окне.

🎯 Специфика роли Тестировщика в C#

Target Framework: Строго указывать версию (например, .NET 9).

Стек тестирования: Запретить смешивать фреймворки (например: "Используй только xUnit, FluentAssertions и Moq").

Контекст кода: Передавать тестировщику не только целевой класс, но и интерфейсы (interfaces), которые он должен замокать.
